Copilot propone y modifica el flujo. La persona configura, prueba y valida.

Objetivo del caso

El participante utilizará Copilot en Power Automate para:

  • Seleccionar una automatización sugerida.
  • Comprender la estructura del flujo.
  • Configurar las conexiones.
  • Probar el funcionamiento.
  • Mejorar el flujo mediante instrucciones progresivas.
  • Agregar condiciones.
  • Incorporar controles de prioridad y presupuesto.
  • Actualizar el estado de la solicitud.
  • Revisar la automatización con Copilot.

Contexto (ficticio · solo fines académicos): una organización del sector energético registra solicitudes de proyectos en una lista de SharePoint. Cada vez que se crea una nueva solicitud, se envía una notificación automática al responsable. Después, el flujo se mejora con Copilot para identificar solicitudes prioritarias, revisar presupuestos altos y actualizar el estado del proyecto.

Todos los nombres, cifras y datos son ficticios. No es una operación real. Copilot no configura automáticamente todas las conexiones ni inserta siempre el contenido dinámico de forma correcta: la persona debe revisar.

Fase 1 · Seleccionar el flujo sugerido

Power Automate + Copilot

  1. Abre Power Automate.
  2. Selecciona Crear su automatización con Copilot.
  3. Entre las sugerencias, elige: «Cuando se cree un nuevo elemento en SharePoint, enviarme un correo electrónico».

Selecciona «Mantener y continuar» para aceptar la propuesta generada por Copilot. No construyas el flujo manualmente desde cero en este paso.

Fase 3 · Configurar el flujo inicial

Desencadenador SharePoint

  • Dirección del sitio (tu sitio de práctica).
  • Nombre de la lista: Solicitudes de proyectos.

Acción Obtener mi perfil

Recupera los datos del usuario conectado. Revisa la conexión de «Usuarios de Office 365»; Copilot no garantiza que la conexión quede lista sola.

Acción Enviar correo electrónico

  • Para: correo obtenido desde «Obtener mi perfil» o correo institucional autorizado de práctica.
  • Asunto: Nueva solicitud registrada: + contenido dinámico Título.

Cuerpo sugerido (los corchetes son contenido dinámico, no texto fijo):

Se ha registrado una nueva solicitud de proyecto. Proyecto: [Título] Solicitante: [Solicitante] Prioridad: [Prioridad] Fecha requerida: [Fecha requerida] Presupuesto preliminar: [Presupuesto preliminar] Estado: [Estado] Responsable: [Responsable] Por favor, revise la información registrada en SharePoint.

Inserta cada campo desde contenido dinámico. No escribas los corchetes como texto fijo.

Fase 5 · Mejorar el flujo con Copilot

Ahora conversa con Copilot. No intentes agregar todas las mejoras en una sola instrucción. Utiliza un prompt por cada modificación.
Mejora 1 · Enriquecer el correo

Objetivo: incluir todos los datos principales de la solicitud.

Modifica la acción de envío de correo para que incluya el título del proyecto, el solicitante, la prioridad, la fecha requerida, el presupuesto preliminar, el estado, el responsable y las observaciones del elemento creado en SharePoint.

Resultado esperado: el correo incluye todos los datos principales de la solicitud.

Validación humana: revisar contenido dinámico (no texto fijo); verificar que las columnas coincidan con la lista.

Mejora 2 · Validar prioridad

Objetivo: crear una condición Prioridad = Alta.

Agrega una condición después de obtener los datos del elemento para comprobar si la columna Prioridad es igual a Alta.

Resultado esperado: condición con ramas Sí / No.

Validación humana: campo Prioridad, valor Alta, mayúsculas/espacios alineados a la lista.

Mejora 3 · Correos diferenciados

Objetivo: asunto distinto según prioridad.

Si la prioridad es Alta, envía un correo con el asunto “Alerta: nueva solicitud prioritaria”. Si la prioridad no es Alta, envía un correo con el asunto “Nueva solicitud registrada”.

Resultado esperado: cada rama envía una notificación distinta.

Validación humana: un solo correo por solicitud; destinatarios correctos; cada correo en su rama.

Mejora 4 · Control presupuestal

Objetivo: alerta si presupuesto > 500000000.

Agrega una condición para identificar si el presupuesto preliminar es superior a 500000000. Cuando sea superior, envía una notificación adicional con el asunto “Solicitud requiere revisión presupuestal”.

Resultado esperado: presupuestos altos generan alerta adicional.

Validación humana: campo numérico; comparación sin puntos ni símbolos; sin alertas duplicadas.

Mejora 5 · Actualizar estado

Objetivo: pasar Estado a «En análisis» tras notificar.

Después de enviar las notificaciones, agrega una acción de SharePoint para actualizar el elemento y cambiar la columna Estado a “En análisis”.

Resultado esperado: el registro cambia de Recibido a En análisis.

Validación humana: mismo sitio/lista; ID del elemento; no borrar otros datos; actualizar solo después del correo.

Mejora 6 · Información incompleta

Objetivo: detectar Responsable o Fecha requerida vacíos.

Agrega una condición para comprobar si el campo Responsable o la Fecha requerida están vacíos. Si falta alguno de estos datos, cambia el Estado a “Información incompleta” y envía un correo indicando qué campo debe completarse.

Resultado esperado: el flujo detecta registros incompletos.

Validación humana: interpretación de vacíos; mensaje preciso; no pasar a En análisis si falta información.

Fase 7 · Copilot como revisor

Pídele a Copilot que audite el flujo. Copia un prompt a la vez:

Explícame este flujo paso a paso en lenguaje sencillo.
Identifica qué conexiones y campos debo revisar manualmente.
Revisa si existe riesgo de enviar correos duplicados.
¿Qué ocurrirá si la prioridad está vacía?
¿Qué ocurrirá si el presupuesto contiene texto o está vacío?
Revisa si el estado del elemento puede actualizarse antes de tiempo.
Sugiere una forma de registrar errores del flujo.
Indica qué partes de esta automatización requieren validación humana.
Propón tres casos de prueba para comprobar que el flujo funciona correctamente.
Identifica posibles problemas de permisos entre SharePoint, Outlook y Usuarios de Office 365.

Laboratorio de prompts

Débil
Mejora el flujo.
Mejorado
Agrega una condición para saber si la prioridad es alta.
Profesional
Agrega una condición después del desencadenador para comprobar si el valor de la columna Prioridad del elemento creado en SharePoint es igual a Alta. Si se cumple, envía un correo con el asunto “Alerta: nueva solicitud prioritaria”. Si no se cumple, envía un correo con el asunto “Nueva solicitud registrada”. No modifiques las conexiones existentes. No elimines las acciones actuales. Indica qué campos debo configurar manualmente.

El prompt profesional funciona mejor porque: define dónde agregar la condición; identifica el campo y el valor; define ambas ramas; protege las acciones existentes; y pide transparencia sobre la configuración manual.

2. ¿Para qué se utiliza Obtener mi perfil?

3. ¿Qué diferencia hay entre texto fijo y contenido dinámico?

4. ¿Qué debe validar la persona después de una modificación hecha por Copilot?

5. ¿Por qué conviene agregar mejoras una por una?

6. ¿Qué riesgo existe al actualizar un elemento de SharePoint?

7. ¿Qué se debe revisar antes de comparar un presupuesto?

8. ¿Copilot reemplaza la prueba del flujo?

Cierre del caso En este primer caso, Copilot no reemplazó el diseño del proceso. Ayudó a crear una versión inicial, agregar reglas y revisar la automatización. El participante conservó el control sobre los datos, las conexiones, las condiciones y la prueba final.
